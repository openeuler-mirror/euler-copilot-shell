# 决策纪律

## 🔴 铁律：做任何涉及外部工具/配置的决策前，必须先查官方文档

本仓库对接多个上游系统（opencode、rpm、openEuler、SkillHub），
其配置语义、API 行为、字段含义均以各自官方文档为准。
**禁止凭猜测、经验或"看名字推断"来决定外部配置的行为。**

### 触发条件

以下任意操作前，**必须**先读取对应官方文档：

| 操作 | 必须先查 |
| ---- | -------- |
| 修改 `opencode.json` 字段（agent/mcp/permission/mode 等） | [opencode.ai/docs](https://opencode.ai/docs/) 对应章节 |
| 修改 RPM spec 宏/钩子/依赖语义 | `rpm.org` 文档或 spec 现有模式 |
| 修改 config.toml 配置项含义 | 对应上游工具文档 |
| 判定"某字段会不会影响某行为" | 查文档确认，不要猜 |

### 判定标准

给出任何关于外部工具行为的断言时，必须能指出文档出处。
"按惯例应该是"、"从命名看是"这种推理不算证据。
如果文档没有明确说明，明确告知用户"文档未覆盖，需验证"，
不要编造结论。

### 设计文档执行纪律

当用户提供设计文档（如 `docs/design/*.md`）要求实施时：

1. **严格按设计文档实施**，每个字段、每个值都对应文档中的明确描述
2. **如果觉得设计有问题**，必须明确向用户提出并附查到的文档证据，**不得静默修改**
3. **如果文档未覆盖的细节需要自行决策**，必须明确告知用户决策依据

## 禁止

- 凭字段名猜测语义就修改外部配置文件
- 不查 opencode 官方 docs 就修改 `opencode.json` 中的 `mode`、`permission`、`agent` 等字段
- 静默偏离设计文档中的任何设计决策
- 为了"优雅"或"直觉"而改变设计文档中明确指定的值
